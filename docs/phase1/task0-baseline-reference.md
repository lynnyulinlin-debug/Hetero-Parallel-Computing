# Task 0 参考记录：CPU 运行基线

> 本记录示范第一阶段 Task 0 应保留的最小环境和正确性证据。它只说明该环境能完成 CPU 构建与回归测试，不构成任何硬件性能结论。

## 输入与环境

```text
硬件状态：CPU-only
执行模式：CPU
构建目录：build/
```

执行命令：

```bash
cmake -S . -B build -DHETEROPAR_ENABLE_TESTS=ON
cmake --build build
ctest --test-dir build -L cpu --output-on-failure
```

应同时记录操作系统、C 编译器、CMake、Python（若运行部署契约）和线程配置；不要只写“默认环境”。

## 证据与判断

| 证据 | 可以确认什么 | 不能确认什么 |
|---|---|---|
| CMake 配置与构建返回码为 0 | 示例能在当前 CPU 环境被构建 | CUDA、NPU 或开发板工具链可用 |
| `ctest -L cpu` 全部通过 | 小规模参考实现与并行候选实现的结果一致 | 并行实现一定比串行实现更快 |
| 单个示例的计时输出 | 当前机器、当前输入和当前线程设置下的观察 | 其他机器、输入规模或设备上的性能 |

## Task 0 结论

- 已建立 CPU 构建和正确性基线，可以进入后续 Task。
- 正确性测试验证结果是否一致；性能结论还需要固定输入、实现、线程配置和测量口径。
- 未安装 CUDA、厂商 SDK 或设备运行时不阻塞第一阶段，但必须在记录中写为“未验证”。
