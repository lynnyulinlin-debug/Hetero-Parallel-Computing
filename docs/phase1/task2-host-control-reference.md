## Host 执行记录

| 示例 | Host 切分与状态 | 等待/同步点 | 可重叠部分 | 当前结论 |
|---|---|---|---|---|
| `ch04_task_pool` | 主线程按 `chunk` 生成任务；工作线程从共享队列取连续区间 | 队列空/满时等待；关闭时唤醒；最终汇合与校验 | 工作线程在取到任务、释放队列锁后并行计算 | 线程生命周期与任务生命周期分离；`chunk` 太小会增加队列成本 |
| `ch05_openmp_blur` | Host 把规则像素循环分配给线程 | 循环结束处汇合；变量作用域决定共享/私有/归约 | 不同图像区间可并行处理 | 规则循环优先使用 OpenMP，而非手写队列 |
| `ch06_simd_layernorm` | Host 保持单个循环控制流，由编译器或指令划分 lane | 向量化循环内不需要任务队列；归约另设同步 | 同一核内多个 lane 处理连续数据 | SIMD 解决局部执行效率，不替代线程级任务调度 |
| `ch07_host_overlap` | Host 按 `chunk` 划分将来可提交给设备的工作 | 每个块的提交、完成和最终校验是同步边界 | 未来可让一块传输/执行时准备下一块 | 本次只验证 CPU 参考；没有 CUDA 时不能声称存在传输或 stream 重叠 |

## Task 2 判断

1. `ch04_task_pool` 的共享状态是队列元数据和关闭状态；输出数组按任务区间独占写入，不应由多个任务竞争同一元素。
2. `ch05_openmp_blur` 中循环索引应为私有，图像输入通常共享只读，归约变量必须使用归约语义而不是普通共享写入。
3. `ch07_host_overlap` 的关键不是“CPU 更快”，而是 Host 是否能在数据位置、提交与收口上避免把 Device 空闲时间浪费掉。
