# 第12章 跨平台编程模型简介

> 本章只回答一个问题：开放异构编程标准在什么场景下值得用。

本章只讨论开放标准在什么场景下值得用。它不展开 CUDA 或 NPU 的核心工程细节，而是说明在“不能只押一个硬件平台”的前提下，OpenCL / SYCL 为什么存在、适合解决什么问题、要付出什么代价。

在本项目里，三类技术的分工是固定的：

- **OpenMP**：CPU 共享内存并行的基础工具，负责把主机侧并行、归约和调度讲清楚。
- **CUDA**：NVIDIA GPU 的主线工具，负责本书的 GPU 编程、性能分析和示例闭环。
- **OpenCL**：跨设备编程标准的补充视角，负责解释“如果必须跨厂商复用，代价是什么”。

在这个分工下：

1. CPU 章节保留 OpenMP，因为它是主机侧工程能力的基线。
2. GPU 主线优先 CUDA，因为本书关注的是可落地、可调优、可验证的主路径。
3. OpenCL 只承担跨平台背景与选型补充职责。
4. 第12章只解释可移植性，不扩写另一套主线。

## 本章要点

1. OpenCL/SYCL 解决可移植性，CUDA 解决成熟生态和性能。
2. OpenCL 的价值在于统一接口层，不在于抹平设备差异。
3. 选型本质是“性能/生态”与“可移植性/避免锁定”的权衡。
4. 只有在必须覆盖多个后端时，开放标准才值得承受额外复杂度。
5. 第12章只负责给第11章和第16章提供背景，不替代它们的决策职责。
