# 第12章 跨平台编程模型简介

> 这一章只回答一个问题：开放异构编程标准在什么场景下值得用。它只做选型补充，不替代 CUDA/NPU 主线。

这一章的定位很明确：它不是主线，不负责把读者带进 CUDA 或 NPU 的核心工程细节；它只负责告诉你，在“不能只押一个硬件平台”的前提下，OpenCL / SYCL 为什么存在、适合解决什么问题、要付出什么代价。

在本项目里，三类技术的分工是固定的：

- **OpenMP**：CPU 共享内存并行的基础工具，负责把主机侧并行、归约和调度讲清楚。
- **CUDA**：NVIDIA GPU 的主线工具，负责本书的 GPU 编程、性能分析和示例闭环。
- **OpenCL**：跨设备编程标准的补充视角，负责解释“如果必须跨厂商复用，代价是什么”。

这意味着：

1. CPU 章节保留 OpenMP，不是因为它代表未来，而是因为它是主机侧工程能力的基线。
2. GPU 主线优先 CUDA，不优先 OpenCL，因为本书要讲的是可落地、可调优、可验证的主路径。
3. OpenCL 不承担主线性能展示职责，只承担跨平台背景与选型补充职责。

## 本章要点

1. OpenCL/SYCL 解决可移植性，CUDA 解决成熟生态和性能。
2. OpenCL 的价值在于统一接口层，不在于抹平设备差异。
3. 选型本质是“性能/生态”与“可移植性/避免锁定”的权衡。
4. 只有在必须覆盖多个后端时，开放标准才值得承受额外复杂度。
5. 第12章只负责给第11章和第16章提供背景，不替代它们的决策职责。
