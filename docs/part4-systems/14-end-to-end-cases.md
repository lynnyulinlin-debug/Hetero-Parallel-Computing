# 第14章 端到端实战案例

> 这一章把 CPU、GPU、NPU 串成真实流水线，展示异构系统如何在工程中协同落地。这里的重点不是单设备极限性能，而是如何把“采集、推理、后处理、调度、显示”组织成可维护的端到端系统。

## 这一章怎么读

本章拆成三个案例，建议按顺序阅读：

1. [案例1：实时视频流人脸检测](14-1-face-detection.md)
2. [案例2：大模型推理的异构调度](14-2-llm-scheduling.md)
3. [案例3：RK3588 + RV1828 的异构视觉方案](14-3-rk3588-rv1828.md)

如果你只想抓住第14章的主旨，可以先看案例1，再看案例3，最后回到案例2理解系统调度的通用方法。

## 统一写法

为了让这一章更像教程而不是散点说明，每个案例都按同一模板写：

1. 问题是什么。
2. 系统怎么分工。
3. 数据怎么流动。
4. 指标怎么看。
5. 图应该怎么画。
6. 现实工程里最容易出什么问题。

这样读者无论先看哪个案例，都能快速定位它在整本书中的角色。

## 本章要点

1. 真实系统是多设备流水线，瓶颈多在阶段衔接与数据搬运。
2. 可切换后端让 GPU/NPU 选型成为工程参数。
3. 队列长度和阶段均值耗时是判断流水线健康度的最小观测集。
4. 设计型案例和可运行案例应该分层描述，避免承诺与现状不一致。
