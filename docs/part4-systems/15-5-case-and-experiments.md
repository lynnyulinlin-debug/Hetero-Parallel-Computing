# 15.5-15.6 回到案例与实验对照

- 在第14章的人脸检测流水线里，队列负责解耦，事件/同步点负责正确性。
- 如果某阶段吞吐不足，先看它是不是被上下游拖住。

### 15.5.1 用第14章理解第15章

第14章案例1可以直接当作第15章的示意图：

- 采集/解码是前置节点。
- 推理是主计算节点。
- 后处理是输出前的收口节点。

把这三个阶段画成 DAG，再把不同设备填进去，就会发现：

- 阶段边界就是同步点边界。
- 队列就是阶段之间的缓冲层。
- 后端切换只是替换某个节点的实现，不应该改整张图。

## 15.6 实验对照

- 切换 `--backend cpu/gpu/npu`，观察阶段输出是否一致。
- 看 `capture_q_max` / `infer_q_max` 和阶段平均耗时，判断瓶颈位置。
- 调整 `frames` 数量，观察流水线重叠的价值。
- 接入真实模型后，再比较队列积压和后处理耗时。

### 15.6.1 读者应该观察什么

运行第14章的流水线时，按下面的顺序看：

1. 先确认输出内容是否一致。
2. 再确认后端切换是否只影响推理阶段。
3. 再看队列是否持续积压。
4. 最后才看吞吐是否提升。

这样读，先确认系统是否保持正确，再看吞吐是否变化。
