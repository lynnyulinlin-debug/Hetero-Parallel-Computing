# 15.2 任务图调度：依赖关系与异步执行

- 把计算建模为 **DAG（有向无环图）**，无依赖的节点并发执行。
- 异步提交 + 事件同步，最大化设备利用率。
- 图建议：至少包含“解码、推理、后处理”三个节点。
- 对第14章案例1的映射：采集/解码先行，推理并行，后处理在输出前同步完成。

### 15.2.1 为什么 DAG 是最小建模单位

DAG 的价值在于，它能把“谁依赖谁”说清楚。  
在异构系统中，这比“线程数多少”“队列开多大”更根本，因为设备协同的前提就是知道哪些节点可以并行、哪些节点必须等待。

以第14章人脸检测为例，最小 DAG 至少包含这三个节点：

- 采集/解码
- 推理
- 后处理

如果有显示或上传，还可以继续往后接。  
这样建模后，读者就能清楚地知道：推理可以和上一帧后处理重叠，但不能越过还没准备好的输入。

### 15.2.2 异步执行和同步点怎么配合

异步提交的目的，是让设备尽量不停下来。  
但异步并不等于“全都不等”，因为总会有一些地方必须同步：

- 输入没准备好，推理不能开始。
- 推理没完成，后处理不能开始。
- 后处理没完成，显示或上传不能开始。

所以真正重要的是：**把同步点放在必要的地方，把等待时间隐藏在可并行的地方**。  
如果同步点太多，流水线就退化成串行；如果同步点太少，结果就可能乱掉。
