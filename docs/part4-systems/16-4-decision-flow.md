# 16.4-16.5 决策流程与结论

## 16.4 决策流程图（一页纸）

- 控制密集、小批次、延迟敏感，优先 CPU 多线程。
- 数据并行明显、模型变化频繁，优先 GPU。
- 模型固定、功耗/体积敏感、量产属性强，优先 NPU。
- 超低延迟且数据流稳定，再考虑 FPGA。

### 16.4.1 一个更实用的决策顺序

按下面的顺序判断：

1. **业务是原型还是量产？**
   - 原型优先 GPU/CPU。
   - 量产优先看 NPU/FPGA。

2. **模型是固定还是频繁变化？**
   - 固定模型更适合 NPU。
   - 频繁变化更适合 GPU。

3. **瓶颈是计算、通信还是延迟？**
   - 计算瓶颈明显，先看 GPU/NPU。
   - 通信复杂，优先简化系统结构。
   - 延迟确定性要求极高，再看 FPGA。

4. **团队有没有对应工具链经验？**
   - 没有经验时，优先选成熟生态，别盲目追求“更专用”的硬件。

## 16.5 结论

- 选型不是“哪个更先进”，而是“哪个更符合约束”。
- 本书语境下，CUDA/GPU 是主线，NPU 是部署延伸，OpenCL/SYCL 是补充，FPGA 是特定场景项。
- 资源有限时，先把一个后端做深做透。
- 这章就是第11章、第14章和第15章的最终决策出口。

### 16.5.1 三个可直接拿去讨论的结论

- 验证阶段优先 GPU 或 CPU，不要一开始就把自己锁进专用硬件。
- 边缘量产阶段优先 NPU，前提是模型和输入输出都比较稳定。
- 需要极低延迟且确定性强时，再考虑 FPGA，但要接受更高开发复杂度。
