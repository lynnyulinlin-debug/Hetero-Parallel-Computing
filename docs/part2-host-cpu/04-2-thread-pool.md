### 4.2.1 线程池为什么更像工程方案

如果 pthread 对应的是“最原始的线程控制”，线程池对应的就是“更像系统服务的线程管理方式”。它的核心价值在于：

- 把线程创建和任务执行解耦；
- 把任务分发和工作线程唤醒解耦；
- 把短任务的调度成本摊薄到线程生命周期中。

这就是为什么高并发服务、批处理任务、异步工作队列几乎都会走线程池，而不是每次来一个任务就新建一个线程。

### 4.2.2 线程池的三个核心部件

一个最简线程池通常由三部分组成：

1. **任务队列**
   - 保存待处理任务。
   - 决定任务排队顺序和等待策略。

2. **工作线程**
   - 从队列中取任务。
   - 执行任务逻辑。
   - 在空闲时等待条件变量唤醒。

3. **调度与退出机制**
   - 决定何时添加任务。
   - 决定何时唤醒线程。
   - 决定线程池何时停止并回收资源。

这三者组合起来，才能把“并行”从一个接口，变成一个可持续运行的工程结构。
