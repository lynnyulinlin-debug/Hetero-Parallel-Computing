# 第7章 CPU端在异构系统中的职责

> 本章理清在 Host+Device 模型里，CPU 不是“算得慢的那个”，而是控制流与数据调度的中枢。

这一章是第二篇的收口：前面第4章讲线程如何承载任务，第5章讲编译级并行如何拆循环，第6章讲单核内部如何向量化，而第7章把这些能力统一放到异构系统里看。CPU 在这里是“编排者”和“数据搬运决策者”，而不是只盯着它的算力。

## 机制骨架

Host 侧的核心机制，其实是三件事：

1. **决定数据放哪儿**
   - 哪些数据留在主存，哪些数据预先驻留在 Device，哪些数据需要频繁往返。
2. **决定什么时候传**
   - 传输能否批量化，能否和计算重叠，能否避免小批量往返。
3. **决定谁来同步**
   - Host 什么时候发起任务，什么时候等待结果，什么时候作为全局调度点收口。

## 7.1 主机端内存管理：页锁定内存（pinned memory）

- 普通可分页内存 vs **页锁定内存（pinned/page-locked memory）**。
- 为什么 pinned memory 能加速 H2D/D2H 传输（DMA 无需经过额外拷贝）。
- 代价：占用物理内存、分配慢，不可滥用。

## 7.2 异步任务提交与同步

- CPU 异步提交任务给 Device，自身继续干别的，用同步点汇合。
- 同步原语：事件、流同步（与第9.7节 Stream 衔接）。

## 7.3 CPU 与协处理器的数据搬运策略

- **核心原则：避免频繁、小批量传输**——PCIe 往返延迟常常盖过计算收益。
- 批量传输、数据驻留 Device、计算与传输重叠。

**本章要点**
1. CPU 在异构系统中承担控制流、数据准备与调度。
2. 页锁定内存加速传输，但占用资源，按需使用。
3. 数据搬运是常见瓶颈，原则是少传、批量传、重叠传。
4. 机制上，Host 的价值不只是发起计算，而是控制驻留、传输和同步的节奏。
