# 6.5 小结：SIMD 在 CPU 体系里的位置

SIMD 的价值，不是替代多线程，而是把单线程内部的吞吐再往上提一层。  
从机制上看，它是“同一条指令驱动多个 lane”的执行模式，依赖向量寄存器、对齐、连续访问和编译器识别。

在工程上，常见顺序通常是：

1. 先把任务并行化。
2. 再让单核内部尽量向量化。
3. 最后在必要时才手写 intrinsics。

这也是为什么第4章、第5章和第6章是能叠加的：线程解决“多个任务怎么分”，OpenMP 解决“循环怎么并”，SIMD 解决“单次计算怎么一次处理更多数据”。

如果把它们放在一起看，CPU 的并行能力其实分成三层：

- **任务层**：线程、线程池、OpenMP 任务/循环调度。
- **数据层**：OpenMP `simd`、自动向量化。
- **执行层**：向量 lane、寄存器宽度、intrinsics。

---

**本章要点**
1. SIMD 是核内数据并行，与多线程可叠加。
2. 优先依赖编译器自动向量化，并用报告验证效果。
3. intrinsics 是最后手段，可控但可移植性差。
4. SIMD 的真正价值，是让 CPU 在不增加线程的情况下继续提升单核吞吐。
5. 机制上，SIMD 不是“更大线程”，而是“更宽执行”。

**动手实验**：用 `-fopt-info-vec` 检查向量加法是否被自动向量化；关闭 `-O3` 对比性能。
