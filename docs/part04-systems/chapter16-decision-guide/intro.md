> 第16章是全书的决策出口。它不再讲怎么写，而是把前面所有技术判断收成一套可直接使用的云边部署与硬件选型框架，面向真正要做取舍的人。

本章分成四个部分：

3. [16.3 从试点到量产](03-production-considerations.md)
4. [16.4-16.5 决策流程与结论](04-decision-flow.md)

## 先看什么

- 建议按“场景选择 -> 开发成本 -> 试点到量产 -> 决策流程与结论”的顺序阅读。
- 先看 [16.1](01-scenario-selection.md)，再看 [16.2](02-cost-model.md)，然后是 [16.3](03-production-considerations.md) 和 [16.4-16.5](04-decision-flow.md)。

## 语境与实验

第16章最适合放进“在约束下做技术取舍”的语境里读。比如：

- 原型阶段先跑通，还是直接为云端服务或边缘量产选型。
- 目标是吞吐、延迟、能效，还是长期可维护性。
- CPU、GPU、NPU 各自适合什么边界条件，以及 FPGA 何时值得作为特殊方案评估。

最小实验不一定是代码实验，更像一个“选型练习”：

1. 选一个业务场景，先判断它更像原型、云端推理、边缘量产还是超低延迟系统。
2. 再列出团队技能、成本、供货和维护约束。
3. 最后把这些约束映射到 CPU / GPU / NPU 上；只有遇到确定性极高、数据流固定的场景，再评估 FPGA。

这个练习的目的，是让读者把“选型”看成约束下的工程判断，而不是技术偏好表态。

### 观察点

- 场景比设备名更重要。
- 隐性成本常常比硬件成本更容易把项目拖慢。
- 试点能跑，不代表量产能稳。

## 本章要点

1. 先看负载特征，再看约束。
2. 开发与维护成本常被低估。
3. 先做单后端闭环，再谈跨平台和多后端扩展。

## 本章小结

第16章是全书的决策出口：把场景、成本、量产约束和团队能力放到一起，先在 CPU、GPU、NPU 三条主线中做判断；只有特殊低延迟场景才进一步评估 FPGA。
