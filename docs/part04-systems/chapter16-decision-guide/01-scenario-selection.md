# 16.1 场景选择：CPU / GPU / NPU 为主，FPGA 作对照

这一节先不谈成本，先谈负载特征。把场景选对，后面的开发和量产判断才有意义。

| 方案 | 最适合 | 不适合 |
|------|--------|--------|
| CPU 多线程 | 控制密集、低并行度、低延迟、快速迭代 | 大规模数据并行 |
| GPU | 训练、多变模型、高吞吐通用并行 | 极低功耗边缘场景 |
| NPU | 固定模型量产、边缘端、能效敏感 | 频繁变更/不支持的算子 |
| FPGA | 超低延迟、定制数据流、长生命周期 | 快速迭代、短开发周期 |

### 16.1.1 典型场景怎么选

你可以把实际项目粗略分成四类：

- **原型验证**
  - 目标是尽快跑通，而不是一次选对最终硬件。
  - 通常优先 GPU 或 CPU，多做实验少做架构锁死。

- **云端/数据中心推理**
  - 目标是吞吐和弹性。
  - 通常优先 GPU，尤其是模型变化快、批量请求多的时候。

- **边缘量产**
  - 目标是功耗、体积、成本和稳定性。
  - 通常优先 NPU，前提是模型基本固定。

- **超低延迟定制系统**
  - 目标是极短的确定性延迟。
  - 才考虑 FPGA，但要接受更高开发成本。

### 16.1.2 容易犯的错误

- 把“能跑”误认为“适合量产”。
- 把“吞吐高”误认为“整体最优”。
- 把“设备更多”误认为“系统更快”。
- 把“模型能导出”误认为“可以直接上线”。

**小结**
场景选择的关键不是设备名，而是工作负载特征和约束条件。先在 CPU/GPU/NPU 三条主线中判断，再把 FPGA 留给确定性极高、数据流固定的特殊场景，通常比一上来问“哪个更强”更靠谱。
