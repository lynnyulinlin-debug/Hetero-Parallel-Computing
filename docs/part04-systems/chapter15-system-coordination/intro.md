## 语境与实验

第15章最适合放进“多设备协同如何稳定工作”的语境里读。比如：

- 采集、推理、后处理三个阶段如何同时推进。
- 多 GPU / GPU+NPU 之间如何拆分任务。
- 跨设备共享数据时，为什么必须显式设计同步点。

最小实验可以直接回到第14章案例1：

1. 观察队列长度、阶段平均耗时和端到端帧率。
2. 调整后端或阶段实现，看看图是否需要改动，还是只改某个节点。
3. 比较“先划分再优化”和“先优化再划分”哪种更容易让系统稳定。

这个实验的目的，是让读者把 DAG、队列和同步点看成一套协同边界，而不是孤立概念。

### 观察点

- 系统协同的核心是边界和同步，不是单点算力。
- 队列和事件往往比单个设备速度更能说明系统健康度。
- 多设备只有在通信和负载匹配时才更有价值。

## 本章要点

1. 工作划分按算术强度、数据量、延迟敏感度决定。
2. DAG + 异步执行是多设备协同的调度基础。
3. 跨设备共享数据时要显式同步。
4. 队列和同步点的设计比单点优化更重要。
5. 第14章案例1提供了本章的最小系统样例。

## 本章小结

第15章把多设备协同的核心矛盾讲清楚了：工作怎么分、依赖怎么画、同步点放哪、数据何时可见。只要这些边界被显式设计，系统协同才会从“能跑”变成“稳定地跑”。
