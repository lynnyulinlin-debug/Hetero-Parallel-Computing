# 第2章 操作系统层面的并行基础

> 本章建立并行执行的操作系统视角：进程/线程、同步、内存可见性，为后续 CPU 并行编程打底。

本章拆成四个部分，建议按顺序阅读：

1. [2.1 进程 vs 线程：并行的基本单位](02-1-process-vs-thread.md)
2. [2.2 线程同步原语：让队列安全运行](02-2-synchronization-primitives.md)
3. [2.3 原子操作与内存屏障：让数据可见](02-3-visibility-and-barriers.md)
4. [2.4-2.5 死锁、活锁与生产者-消费者](02-4-deadlock-and-producer-consumer.md)

## 本章怎么读

1. 先看 [2.1](02-1-process-vs-thread.md)，建立“并行执行单位”的直觉。
2. 再看 [2.2](02-2-synchronization-primitives.md)，理解共享数据为什么要受控访问。
3. 然后看 [2.3](02-3-visibility-and-barriers.md)，搞清楚“写了”为什么不等于“看见了”。
4. 最后看 [2.4-2.5](02-4-deadlock-and-producer-consumer.md)，把前面所有机制放进一个任务队列里串起来。

## 统一案例

第2章不是把几个 OS 概念简单并列，而是围绕一个最小系统来组织：

- 主线程不断接收任务。
- 工作线程从队列里取任务并处理。
- 队列为空或满时，线程要等待。
- 多个线程同时读写共享数据时，必须靠同步原语和内存可见性保证正确性。

这个案例会在第4章变成线程池，在第7章变成 Host 侧任务编排，在第14章变成采集、推理、后处理的流水线。

## 本章要点

1. 进程隔离、线程共享，决定了通信方式和切换开销。
2. 同步原语解决竞态，但也引入等待、阻塞和死锁风险。
3. 原子操作与内存屏障保证多核下的可见性与顺序。
4. 生产者-消费者是理解本章所有概念的最小系统案例。
5. 第2章的目标不是背 API，而是把并行执行的底层机制看成一个可协调的任务系统。
