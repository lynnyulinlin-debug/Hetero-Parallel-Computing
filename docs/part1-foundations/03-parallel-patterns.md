# 第3章 并行模式入门

> 这一章解决什么问题：掌握一套描述并行计算的通用词汇，后续 CPU/GPU/NPU 章节都会反复用到这些模式。

沿着前两章的脉络往上看，这一章开始把那些实现机制整理成 Map/Reduce、数据并行、任务并行和流水并行这些可复用的描述方式。读到这里，读者应该能把一个并行程序翻译成“它属于哪种模式、为什么这样拆、适合哪类硬件”。

## 3.1 基本并行模式

- **Map（映射）**：对每个元素独立施加同一操作（向量加法就是 Map）。
- **Reduce（归约）**：将一组值合并为一个（求和、求最大）。
- **Scatter/Gather**：按索引分散/收集数据。

## 3.2 任务并行 vs 数据并行

- **数据并行**：同一操作作用于大量数据（GPU 的主场）。
- **任务并行**：不同任务并发执行（CPU 流水线、异步阶段）。

## 3.3 吞吐量 vs 延迟（📋 产品经理重点）

- **延迟**：单个请求多快完成。**吞吐量**：单位时间处理多少。
- 加速器优化吞吐，常以牺牲单次延迟为代价；选型时要分清你真正要的是哪一个。

**本章要点**
1. Map/Reduce/Scatter/Gather 是描述并行计算的通用积木。
2. 数据并行偏 GPU，任务并行偏 CPU 流水线。
3. 📋 吞吐与延迟是不同目标，决定硬件与架构选择。
