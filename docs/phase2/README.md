# 第二阶段专题路线

> 第二阶段从第一阶段 Task 0-6 的最小工程闭环出发，按实际工作方向深入。它不是下一轮“全书必修”，每次只选择一个专题，并交付可复测结果。

## 进入条件

- 已完成 [第一阶段验收包](../phase1/README.md)，或能提供等价的构建、正确性、测量和部署报告证据。
- 明确一个目标平台、模型或系统场景；不在同一专题中同时引入多个厂商后端。
- 真实设备结果必须记录硬件、运行时、输入、测量口径和失败条件。

## 专题选择

| 专题 | 适用问题 | 首个交付 | 当前状态 |
|---|---|---|---|
| 云端 GPU | CUDA 算子、服务吞吐、多设备协同 | 一份 profile 与优化对照 | 教程已有算子基础，真实服务案例待补 |
| [数据中心 AI 加速器：昇腾/CANN](ascend-cann.md) | 私有化或云端固定模型推理 | ONNX -> OM -> 真实运行时报告 | 仅完成专题边界和验收契约 |
| [边缘 AI：Jetson](../../examples/ch14_face_detection/platforms/jetson-orin-nano/README.md) | 视频输入到 TensorRT 报告 | 固定视频基线实测 | 4GB 实验配置已冻结，待板端接入 |
| [边缘 NPU：RK3588](../../examples/ch14_face_detection/platforms/rk3588/README.md) | 量化、转换和 NPU 约束对照 | 与 Jetson 相同输入的部署记录 | 教学脚手架已有，真实后端待补 |
| 可移植性 | OpenCL / SYCL 取舍 | 一个跨平台构建与测量对照 | 第12章按需选读 |
| 系统工程 | 任务图、背压、成本和维护 | 一个端到端系统改动与复测 | 章节与模拟项目已有 |

## 共用验收规则

1. 先固定输入、正确性基线和测量口径，再讨论性能。
2. 一个报告只描述一个平台与一个执行模式；`simulated`、CPU 对照和真实设备数据不能混写。
3. 若比较平台，模型、输入、精度、批量和指标定义必须相同，并保留不具可比性的限制。
4. 真实工具链不可用时，记录失败条件并停止在接口/契约层，不补造性能数字。

第二阶段不替代 [教程架构](../ARCHITECTURE.md) 或章节目录；它只定义项目化深入时的选择与验收边界。
