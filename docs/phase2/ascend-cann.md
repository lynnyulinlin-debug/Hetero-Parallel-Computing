# 数据中心 AI 加速器专题：昇腾与 CANN

> 本专题把昇腾视为云端或私有化数据中心的 AI 加速器路径，而不是“国产方案”标签或边缘 Jetson/RK3588 的替代品。目标是完成一个固定模型的真实转换、运行与报告闭环。

## 适用范围

- 平台：以昇腾 910B 等数据中心 AI 加速器为代表；具体型号、固件和兼容性必须由实机确认。
- 工具链：CANN 与对应运行时；本仓库不捆绑 SDK、驱动、模型权重或设备。
- 场景：稳定模型、固定输入形状或可控动态形状的离线/在线推理。

它与第一阶段和边缘路径的关系：

```text
第一阶段：理解部署链路和报告边界
    -> 第二阶段昇腾：ONNX -> OM -> CANN runtime -> 实测报告
    -> 可选对照：同一模型、输入与精度下的 CUDA 或其他后端
```

## 项目链路

| 阶段 | 输入 | 产出 | 验收问题 |
|---|---|---|---|
| 模型冻结 | ONNX、输入 shape、测试集 | 模型版本与正确性基线 | 运行前后输出如何比较？ |
| 转换 | ONNX、目标 SoC/芯片、精度策略 | OM 工件与转换日志 | 哪些算子、shape 或精度限制导致失败？ |
| 运行 | OM、同一批输入、CANN runtime | 原始推理结果与计时 | 延迟、吞吐和失败来自哪里？ |
| 报告 | 硬件、软件、输入、计时 | 可归档 JSON/Markdown 报告 | 结论是否可复测且没有跨平台误比？ |

转换与运行命令取决于 CANN 版本、硬件和模型，不能在没有实机的情况下写成仓库保证可运行的命令。真实接入时应把实际命令、退出码和完整日志路径放进报告。

## 真实报告契约

首份报告至少包含下列字段。字段名称可由后续适配器实现为 JSON schema，但语义不得省略。

```text
execution_mode: real
platform: Ascend <model>
cann_version / driver_version / firmware_version
model_source: ONNX 路径或模型版本
compiled_model: OM 工件标识与哈希
precision: FP16 / INT8 / ...
input: 数据集或固定输入标识、shape、样本数、哈希
warmup_runs / measured_runs / batch_size
latency_ms_p50 / latency_ms_p95 / throughput
correctness: 与参考输出的误差口径或精度指标
failure_conditions: 转换、运行或数据侧的已知限制
```

只有在同一模型、输入、精度、batch、预热和统计方法下，才可与 CUDA 或其他后端比较。模型转换耗时、首次加载与稳态推理必须分开记录。

## 当前建设状态

- 已有：第11章通用导出、量化、转换、推理的教学链路，以及 `simulated`/`real` 报告边界。
- 未有：真实 `atc` 转换、ACL/CANN 运行时适配器、910B 实机报告、统一的跨后端基准数据。
- 下一步：在可用昇腾设备上选择一个小模型和固定测试集，先完成单后端正确性与报告，再决定是否做 CUDA 对照。

不要把教学模拟输出或其他 NPU 的结果标记为昇腾测量。
