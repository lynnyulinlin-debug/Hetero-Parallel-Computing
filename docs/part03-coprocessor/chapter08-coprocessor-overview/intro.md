# 第8章 Device 执行模型与加速器选择

> 中心问题：一项负载是否值得越过 Host/Device 边界，又应进入 GPU 编程路径还是 AI 加速器部署路径？

第8章是第三篇的共同入口，先固定后续两条主线都需要的三个判断：

1. 数据为什么必须在 Host 和 Device 之间搬运。
2. GPU 和 NPU 为什么不是同一种协处理器。
3. 到底该不该把一个问题放到加速器上做，并部署在云端还是边缘端。

第7章已从 Host 侧固定数据所有权、提交节奏和同步边界；第8章不重讲这些控制决策，而是转向 Device 的执行与内存特征，并据此判断负载是否值得越过 Host/Device 边界。

本章不是设备能力展示，也不开始讲 CUDA API 或厂商 SDK。它只建立门槛：Host/Device 边界、设备类别、算术强度与部署位置。完成判断后，进入第9章走 GPU 编程路径，或进入第11章走 AI 加速器部署路径。

本章分成三个部分：

1. [8.1 主-从内存模型：Host ↔ Device](01-host-device-memory-model.md)
2. [8.2 协处理器的分类](02-accelerator-types.md)
3. [8.3-8.4 性能指标与计算密度判断](03-metrics-and-roofline.md)

## 语境与实验

第8章最适合放进“先判断要不要上加速器”的语境里读。比如：

- LLM 推理里，为什么有些阶段更像计算密集，有些阶段更容易被搬运拖慢。
- 图像处理里，为什么某些任务算力看起来很多，但实际并不一定适合先上 Device。
- 批处理任务里，为什么数据规模、复用率和传输成本比峰值算力更重要。
- 云端和边缘端之间，为什么同一个模型会因批量、网络、功耗和输入位置而采用不同后端。

最小实验可以先从本书已有的简单任务入手：

1. 对比 `examples/ch09_vec_add` 和 `examples/ch09_reduce` 的负载特征。
2. 用算术强度去粗略判断它们更接近“带宽受限”还是“计算受限”。
3. 想一想如果再加上传输开销，哪类任务更可能被 Device 真正放大收益。

这个实验的目的，是让读者先形成“是否值得上加速器”的门槛感，而不是直接跳进设备实现。

### 观察点

- 算力高不等于收益高，数据搬运和复用率往往先决定结果。
- 低算术强度任务更容易被带宽和传输主导。
- 先判断是否值得上加速器，通常比先选设备更重要。

## 本章要点

1. Host/Device 各自独立内存，数据搬运是核心复杂性。
2. GPU 通用、NPU 专用，设计哲学不同。
3. 📋 用算术强度判断是否值得上加速器，别被"峰值算力"误导。
4. 第8章的作用不是展示性能，而是先建立“是否值得上加速器”的判断门槛。
5. 第8章是从 CPU 主线过渡到 GPU/NPU 主线的正式入口。

## 本章小结

第8章先把异构系统最关键的边界讲清楚：Host 和 Device 不是同一块内存，GPU 和 NPU 不是同一种协处理器。理解这两个前提后，后面的 CUDA 编程、profiling 和 NPU 部署才有共同的判断坐标。
