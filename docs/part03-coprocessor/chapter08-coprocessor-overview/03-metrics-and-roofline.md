# 8.3-8.4 性能指标与计算密度判断

## 8.3 关键性能指标

峰值算力、带宽、延迟和功耗不是互相独立的“名词列表”，而是一组判断系统瓶颈的坐标轴。

这一节的目标，是把“加速器很强”这句话拆成可以判断的工程指标。  
只要你能看懂算力、带宽、延迟和功耗之间的关系，就能更准确地判断一个问题到底是算力受限，还是数据搬运受限。

- 峰值算力（FLOPS/TOPS）、内存带宽（GB/s）、延迟、功耗（TDP）。
- **算术强度（arithmetic intensity）= 计算量 / 数据传输量**，决定受限于算力还是带宽（Roofline 模型雏形）。

这里最关键的机制判断是：如果你的问题“算得不够多、传得太多”，那上更大的加速器未必有用；如果你的问题“每搬一次数据都能产生很多计算”，加速器才更可能兑现收益。

## 8.4 📋 产品经理视角：如何估算计算密度决定是否上加速器

- 计算密度低（如向量加法）→ 带宽受限，加速器收益有限。
- 计算密度高（如矩阵乘、卷积）→ 算力受限，加速器威力尽显。
![图 8-2：Roofline 中的算子定位与优化选择](../../assets/figures/fig-08-roofline-decision.svg)

*图 8-2：`vec_add` 更接近带宽受限，`reduce` 还受同步影响，GEMM 更接近计算受限。先定位算子受哪条上限约束，再决定优先减少搬运、降低争用还是提高数据复用。*

这一节是第8章最核心的判断层：**先算算术强度，再谈上不上加速器**。  
如果计算量相对传输量太低，那么问题大概率会被带宽和搬运成本限制；只有当每次搬运都能带来足够多的计算时，GPU 或 NPU 才更可能把优势兑现出来。

第8章先帮助你回答两个判断问题：

1. 这件事是算力受限，还是带宽受限？
2. 如果受限的是带宽，那么把计算搬到更大的 GPU/NPU 上，是否真的能改变瓶颈？

---

**本章小结**
第8章真正要建立的是门槛判断，而不是设备崇拜。先判断任务是算力受限还是带宽受限，再判断数据搬运是否值得，最后才谈上不上加速器。这样进入第9章时，CUDA 就不再是“该不该用”的问题，而是“怎么用得对”的问题。

**本章要点**
1. Host/Device 各自独立内存，数据搬运是核心复杂性。
2. GPU 通用、NPU 专用，设计哲学不同。
3. 📋 用算术强度判断是否值得上加速器，别被"峰值算力"误导。
4. 第8章的判断框架，是第9章 GPU 主线和第11章 NPU 部署的共同前提。
