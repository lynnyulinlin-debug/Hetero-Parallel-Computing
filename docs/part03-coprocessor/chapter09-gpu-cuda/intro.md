## 语境与实验

第9章最适合放进“把一个真实计算任务写成 CUDA kernel”的语境里读。比如：

- 向量加法：看带宽和传输开销。
- 归约：看同步、原子和共享内存。
- 矩阵乘：看分块、复用和计算受限场景。

最小实验可以直接沿用本章已有案例：

1. 先跑 `examples/ch09_vec_add`，对比 CPU 串行、OpenMP 和 CUDA。
2. 再跑 `examples/ch09_reduce`，看朴素版和共享内存版的差别。
3. 最后对照矩阵乘示意，思考为什么同样是 GPU，瓶颈类型会完全不同。

这个实验的目的，是让读者把 CUDA 从“语法”看成“映射方式 + 内存层次 + 执行节奏”的组合。

### 观察点

- 线程层次决定任务如何拆，内存层次决定数据如何复用。
- 小任务时，传输和启动开销会更显眼。
- 同样是 GPU，带宽受限和计算受限的优化手段并不相同。

## 本章要点

1. CUDA 三级线程层次 + 多级内存层次是性能优化的基础。
2. 向量加法（带宽受限）vs 矩阵乘（计算受限）揭示加速器的适用边界。
3. 共享内存与流是两大优化杠杆：复用数据、重叠传输。
4. ⚡️ 警惕分支发散、bank 冲突、未检查的内存错误。

## 本章小结

第9章把 GPU 编程的骨架搭起来了：线程层次决定映射方式，内存层次决定复用策略，kernel 启动和 stream 决定执行节奏，实战案例决定你能否真正把这些机制串起来。下一章会把视角切到“怎么测”，把优化从猜瓶颈转成找证据。
