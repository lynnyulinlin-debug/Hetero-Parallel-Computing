**小结**
第9章最后要记住的不是某个 API，而是性能和正确性都会被细节拖垮：分支发散、bank 冲突、边界越界和错误的内存策略，都会让前面的并行设计失效。下一章会把这些经验收束成一条更稳的诊断流程：先看时间线，再看核函数，再回到代码改动。

**本章要点**
1. CUDA 三级线程层次 + 多级内存层次是性能优化的基础。
2. 向量加法（带宽受限）vs 矩阵乘（计算受限）揭示加速器的适用边界。
3. 共享内存与流是两大优化杠杆：复用数据、重叠传输。
4. ⚡️ 警惕分支发散、bank 冲突、未检查的内存错误。

**动手实验**：先跑通 `examples/ch09_vec_add`，再完成 `examples/ch09_reduce`，最后用第10章 profiler 对比朴素归约和共享内存归约的时间线差异。
