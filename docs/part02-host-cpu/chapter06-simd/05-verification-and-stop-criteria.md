# 6.5 验证向量化与停止优化

SIMD 优化的完成条件不是“写了 pragma”或“用了 intrinsics”，而是确认编译器确实生成了向量代码、数值结果保持正确，并且收益值得维护成本。

## 先验证，再解释时间

1. **正确性**：用标量参考实现对照输出，特别检查尾部元素和边界输入。
2. **编译证据**：查看编译器向量化报告，例如 GCC 的 `-fopt-info-vec`；报告未向量化时先检查依赖、别名和访问模式。
3. **测量口径**：在同一输入、编译选项和线程配置下比较标量与候选实现；不要把一次运行当作结论。
4. **瓶颈判断**：若循环已受内存带宽、缓存未命中或上层同步限制，继续扩大向量宽度可能没有端到端收益。

## 何时停止

满足任一条件就应停止继续手工向量化，转而检查更高层的瓶颈：

- 自动向量化已生成目标指令，且数值与性能达到当前目标。
- 改成 intrinsics 只带来不稳定的微小变化，或降低了可移植性与可读性。
- 性能主要受数据搬运、线程同步、缓存容量或 Device 交接限制。

这时应回到第5章检查循环调度，或进入第7章检查数据路径和同步边界，而不是继续增加 intrinsics。

**小结**
SIMD 是局部优化。正确性、编译证据和稳定测量三者齐全后，才判断是否值得维护；局部循环不再是主瓶颈时，应停止在这一层继续优化。
