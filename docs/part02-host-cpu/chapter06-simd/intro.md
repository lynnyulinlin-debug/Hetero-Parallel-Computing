# 第6章 SIMD：指令级数据并行

> 中心问题：在任务和循环已经划分后，单个 Host 线程如何让一条指令处理多个连续数据元素？

SIMD 的机制核心，是把一个标量操作扩展成“向量 lane 上的并行执行”。读这章时要始终记住：它不是多线程的替代品，而是单个线程内部的并行能力，常常和多线程叠加使用。

第4、5章解决任务与循环的工作划分；本章处理单核内部的 lane 利用率。三者可以叠加：OpenMP 分配循环迭代，SIMD 加速每个线程正在执行的局部循环。

## 语境与实验

第6章最适合放进“单核内部还能继续提吞吐”的语境里读。比如：

- 图像滤波里的逐像素计算。
- 向量加法、归一化、激活函数这类规则计算。
- 任何“同一个操作重复做很多次”的 CPU 热点路径。

最小实验可以围绕同一个计算做三种版本：

1. 标量版：只看基线。
2. 自动向量化版：让编译器尽量自己识别。
3. intrinsics 版：在必要时手动控制向量化。

用 [ch06_simd_layernorm](../../../examples/ch06_simd_layernorm/README.md) 对照后，记录三项证据：

- 运行时间有没有稳定下降。
- 编译器是否真的生成了向量化代码。
- 对齐、数据布局和循环形态是否影响了结果。

规则、重复、连续的数据最容易受益。应先尝试自动向量化并检查编译器报告；intrinsics 是最后手段，因为它提高控制力的同时也降低可移植性。数据布局不合适时，单纯增加向量宽度不会自动带来收益。

## 本章小结

第6章说明 SIMD 是单线程内部的并行杠杆：先验证编译器是否已生成向量代码，再决定是否需要 intrinsics。线程、OpenMP 和向量化不是互相竞争的方案，而是可叠加的三个层次。下一章把它们放回 Host/Device 数据移动和同步的控制面。
