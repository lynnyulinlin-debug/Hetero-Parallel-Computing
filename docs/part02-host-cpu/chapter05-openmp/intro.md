# 第5章 OpenMP：循环级数据并行

> 中心问题：面对规则、可切分的循环，怎样让编译器和运行时承担线程管理，同时仍能明确数据作用域与调度策略？

第4章把线程、队列和关闭协议全部暴露出来；这一章把规则循环的并行意图交给 OpenMP 表达。机制没有消失，只是从“手写线程控制”转成“声明并行范围、变量归属和调度策略”。

## 语境与实验

第5章最适合放进“循环密集型 CPU 程序”的语境里读，比如：

- 图像滤波和模糊处理。
- 批量数组变换。
- 规则、重复、可切分的大循环。

最小实验使用 [ch05_openmp_blur](../../../examples/ch05_openmp_blur/README.md)：

1. 跑第5章的 blur 示例，对比串行和 OpenMP。
2. 改变线程数和调度策略，观察负载均衡是否变好。
3. 刻意改错共享/私有变量，观察结果为什么会失真。

最小产出不是某个固定加速比，而是一条对照记录：循环变量和临时变量的归属、选用的 `schedule`、数值是否正确，以及负载不均是否改变了结果。规则循环越明显，OpenMP 越容易兑现收益；共享变量划分不清时，结果通常先于性能出问题。

## 本章小结

第5章把“线程并行怎么做”提升成“并行意图怎么声明”：循环拆分、数据归属和调度策略都成为可检查的选择。下一章继续向下走一层，观察单个线程如何借助 SIMD 提高局部吞吐。
