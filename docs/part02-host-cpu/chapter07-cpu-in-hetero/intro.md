# 第7章 Host-Device 协同：数据、异步与同步

> 本章把 CPU 放回 Host 控制面：它负责控制流、数据调度、异步提交与同步收口。

第4章说明任务如何被线程承载，第5章说明规则循环如何拆分，第6章说明单核如何提高局部吞吐。本章不再增加一种 CPU 并行 API，而是回答这些能力进入异构系统以后服务什么：让数据在正确的时间出现在正确的位置，让 Device 有连续工作，让结果在明确的边界收口。

Host 的工作可归为三类决策：

1. **数据放置**：哪些数据留在主存，哪些数据驻留 Device，哪些数据需要回传。
2. **提交节奏**：任务如何分块，传输能否批量化，CPU 是否能在 Device 工作时继续准备下一批。
3. **同步边界**：结果何时可用，缓冲区何时可复用，谁负责把多个阶段的结果收口。

这三类决策共同决定端到端效率。CPU 在这里不是另一颗较慢的算力芯片，而是系统的节奏控制器。

第7章只从 Host 侧回答“数据谁拥有、何时移动、何时等待”。第8章才从 Device 侧解释内存层次、协处理器差异和是否值得把负载交给加速器；两章共享边界，但不重复同一个判断。

## 本章结构

1. [7.1 数据放置与页锁定内存](01-data-placement-and-pinned-memory.md)：理解 Host/Device 内存边界与 pinned memory 的代价。
2. [7.2 异步提交与同步收口](02-async-submission-and-synchronization.md)：区分提交、执行、等待和结果可见性。
3. [7.3 数据搬运与流重叠](03-transfer-and-stream-overlap.md)：用分块、驻留和重叠减少传输路径的空转。

## 语境与实验

第7章适合放进真实流水线理解：视频系统里 Host 负责采集、排队与收口；大模型服务里 Host 负责 tokenization、batch 组装与请求调度；图像加速里 Host 决定数据是否驻留、何时搬运、何时等待。

配套实验是 [ch07_host_overlap](../../../examples/ch07_host_overlap/README.md)。先运行 CPU 路径，观察分块与收口；有 CUDA 环境时再比较 pinned memory、异步拷贝和多 stream 的重叠。实验验证的是机制与正确性，不应把本地结果当作其他设备的性能结论。

## 本章小结

Host-Device 协同的核心不是“把更多工作交给 Device”，而是减少不必要的数据往返、延后不必要的等待，并在必须等待时准确收口。读完本章后，第8章会从 Device 视角继续建立 Host/Device 内存边界、协处理器分类和上加速器的判断条件。
