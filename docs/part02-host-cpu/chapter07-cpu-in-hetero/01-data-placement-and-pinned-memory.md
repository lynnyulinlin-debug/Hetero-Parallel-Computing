# 7.1 数据放置与页锁定内存

异构程序首先要回答的不是 kernel 如何写，而是数据在哪里。Host 主存和 Device 内存通常是独立空间；一旦数据需要跨边界，传输时间、缓冲区生命周期和复用方式都会进入总成本。

## 先建立数据驻留模型

对每类数据先做三个判断：

1. **谁生产，谁消费**：输入来自 Host、Device 还是外部设备；结果是否真的需要回到 Host。
2. **会被使用多少次**：只用一次的数据可能只值得一次批量传输；反复使用的数据更适合驻留 Device。
3. **何时允许覆盖**：提交异步传输后，Host 缓冲区和 Device 缓冲区都不能在操作完成前被错误复用。

例如，模型权重通常适合长期驻留 Device；每帧图像可能需要持续上传；只供 Device 下一阶段使用的中间结果通常不应先回传 Host。把每一步都搬回 Host，会把 Device 当作一次性函数调用，而不是流水线中的执行阶段。

## 页锁定内存解决什么问题

普通主存可被操作系统换页。页锁定内存（pinned 或 page-locked memory）固定物理页，使 DMA 传输路径不需要额外的可分页缓冲步骤，因此常用于 Host 到 Device 或 Device 到 Host 的异步传输。

它不是默认分配方式，代价包括：

- 占用不可换出的物理内存；
- 分配和释放成本更高；
- 过度使用会挤压操作系统和其他进程的可用内存。

因此，只有在传输位于关键路径、缓冲区会重复使用、并且后续确实要启用异步拷贝或重叠时，才有理由采用 pinned memory。

## 常见错误

- 每个小请求都临时申请 pinned memory，分配成本反而进入热路径。
- Device 已经能够消费的数据仍先拷回 Host 再传回 Device。
- 把“使用 pinned memory”误认为一定更快，却没有测量传输是否真是瓶颈。

**小结**
数据放置决定传输是否存在，驻留策略决定传输是否重复，缓冲区生命周期决定异步操作是否安全。下一节讨论：数据已经确定放置后，Host 如何提交工作而不立即阻塞。
