# 教学实验：OpenMP 图像模糊

> 对应章节：第5章。这个实验用最小的 3x3 stencil 说明 OpenMP 的循环并行、共享/私有变量和调度方式是怎么影响吞吐的。

## 实验目标

- 先把一个规则循环并行化。
- 再观察 `schedule`、线程数和图像尺寸如何影响收益。
- 最后理解“OpenMP 适合循环密集、规则访问、边界清晰”的前提。

## 运行

```bash
make run
./openmp_blur 1024 768 8
```

参数含义：

- `width`：图像宽度，默认 `1024`
- `height`：图像高度，默认 `768`
- `threads`：OpenMP 线程数，默认 `4`

## 文件结构

| 文件 | 说明 |
|------|------|
| `blur_serial.c` | 串行 3x3 模糊，作为黄金参考 |
| `blur_openmp.c` | OpenMP 并行版本，按行并行 |
| `main.c` | 对比驱动：计时 + 校验 + 加速比报告 |
| `blur.h` | 公共声明 |
| `Makefile` | 仅需 OpenMP 即可构建 |

## 教学要点

- 这个实验不是为了“把图像处理做完整”，而是为了看一个规则循环如何被拆给多个线程。
- 图像模糊天然有边界条件，适合讲共享数据、临时变量和循环归属。
- 和第4章相比，这里不再强调任务队列，而是强调“循环怎么分配给线程”。
- 和第6章相比，这里还没有深入到 SIMD，而是先把线程级并行讲稳。

## 推荐观察

1. 固定图像尺寸，改变线程数，看加速比是否稳定提升。
2. 固定线程数，改变分辨率，看并行开销在小图上是否更明显。
3. 把并行策略改成仅按行拆分或 `collapse(2)`，比较负载均衡差异。

## 动手实验

1. 把模糊核从 `3x3` 改成 `5x5`，观察计算量增加后加速比是否更好。
2. 把 `threads` 设为 1、2、4、8，记录每档耗时。
3. 把输入图像换成更不规则的边界模式，观察边界处理是否影响结果一致性。
