# Jetson Orin Nano 4GB：首轮实验配置

> 配置 ID：`jetson-orin-nano-4gb-video-baseline-v1`。这是计划配置，不含任何实测性能数字；版本、模型和功耗模式必须由首次板端报告补全。

## 固定项

| 项目 | 首轮配置 | 原因 |
|---|---|---|
| 设备 | Jetson Orin Nano 4GB | CPU、GPU、解码器共享系统内存，需要预留余量 |
| 输入 | 单个本地视频文件，最大 1280x720 | 先消除网络和摄像头波动，观察完整解码到后处理链路 |
| 模型 | 轻量人脸检测 ONNX/TensorRT engine | 模型必须在静态图片预检通过后才能进入视频测量 |
| 推理精度 | FP16 | 首轮优先控制内存和延迟；不把 FP32 作为基线 |
| batch | 1 | 边缘视频以单帧延迟为主，不用 batch 掩盖排队时间 |
| 模型输入 | 首选 416x416，可降为 320x320 | 640x640 只在内存和时延余量充足时采用 |
| 队列长度 | 2 | 限制积压和帧缓存，仍可观察阶段重叠 |
| TensorRT workspace | 512 MiB 上限 | 避免 engine 构建或运行时挤占共享内存 |
| 预热与测量 | 30 帧预热，300 帧测量 | 预热不进入 FPS、P50/P95 统计 |

## 内存预算与停止条件

4GB 为系统共享内存，不是可独占显存。首轮报告必须记录 `memory_peak_mb` 和 `swap_peak_mb`，并使用 `tegrastats` 或等价工具采集峰值。

| 状态 | 条件 | 动作 |
|---|---|---|
| 正常 | 峰值内存低于 3000 MiB，且不使用 swap | 保持配置，继续记录延迟和队列 |
| 警戒 | 3000-3300 MiB，或出现持续队列积压 | 降低模型输入到 320x320，确认 workspace 未超过 512 MiB |
| 停止 | 高于 3300 MiB、出现 OOM 或持续 swap | 停止性能比较，先减少输入尺寸、队列或进程占用 |

这些阈值用于保护 4GB 设备上的首轮实验，不是 Jetson 平台的通用规格结论。

## 执行顺序

1. 用单张图片验证 engine、输入尺寸、预处理和检测框；不记录性能结果。
2. 计算固定视频的 SHA-256，记录视频分辨率、帧率和路径或稳定标识。
3. 在固定功耗模式、固定 engine 和固定视频下完成 30 帧预热与 300 帧测量。
4. 写出包含配置 ID、内存峰值、swap 峰值、FPS、P50/P95 的真实报告。
5. 仅当首轮报告稳定后，再单独测试 640x640、摄像头或 RTSP；它们不能直接与此基线比较。

## 报告绑定

调用 `pipeline.py --mode real` 时，报告必须包含：

```json
{
  "experiment_config_id": "jetson-orin-nano-4gb-video-baseline-v1",
  "memory_peak_mb": 0,
  "swap_peak_mb": 0
}
```

其余必填字段见 [固定视频验收基线](video-baseline.md)。
