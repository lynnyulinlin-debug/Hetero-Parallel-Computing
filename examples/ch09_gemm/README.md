# 教学实验：GEMM 的分块与共享内存

> 对应章节：第9章、第10章、第13章。这个实验把 GEMM 作为“计算受限基准”，用来观察分块、共享内存复用和 profiler 指标之间的对应关系。

## 实验目标

- 先看串行、OpenMP 和 CUDA 三种实现的差异。
- 再把“计算受限”和“数据复用”这两个概念落到真实代码。
- 最后理解为什么 GEMM 是 ML / LLM 系统里最基础的性能锚点。

## 运行

```bash
make run
make USE_CUDA=1 run
./gemm 512
```

参数含义：

- `n`：矩阵边长，默认 `512`

## 文件结构

| 文件 | 说明 |
|------|------|
| `gemm_serial.c` | 串行三重循环，黄金参考 |
| `gemm_openmp.c` | OpenMP 并行版，按输出元素拆分 |
| `gemm_cuda.cu` | CUDA 分块版，演示 shared memory 和 tile 调度 |
| `main.c` | 对比驱动：计时 + 校验 + 加速比报告 |
| `gemm.h` | 公共声明 |
| `Makefile` | 默认 CPU-only，可选启用 CUDA |

## 教学要点

- GEMM 是典型的计算受限算子，和 `vec_add` 的带宽受限形成鲜明对照。
- 它的关键不只是“并行”，而是“把同一块数据多次复用起来”。
- CUDA 版的 tile + shared memory 写法，正好对应第9章的内存层次和第10章的性能分析。

## 推荐观察

1. 先从 `n=256/512` 跑起，再放大到 `1024` 看趋势是否稳定。
2. 对比串行和 OpenMP，理解 CPU 侧并行化的收益上限。
3. 对比串行和 CUDA，理解计算受限任务为什么更容易放大 GPU 收益。
4. 用 `nsys` / `ncu` 观察分块前后，核函数耗时和内存流量的变化。

## 动手实验

1. 把 CUDA tile 尺寸从 `16` 改成 `8` / `32`，观察性能变化。
2. 把 OpenMP 的 `collapse(2)` 改成仅并行外层 `i`，观察负载均衡差异。
3. 对比不同 `n` 下 CPU 与 GPU 的交叉点，判断何时 GEMM 开始真正适合上 Device。
