# 教学实验：SIMD LayerNorm

> 对应章节：第6章。这个实验用 row-wise LayerNorm 说明“单线程内部如何继续提吞吐”，重点看编译器自动向量化、`#pragma omp simd` 和数据布局。

## 实验目标

- 先用串行版本建立黄金参考。
- 再用 `omp simd` 让编译器对归约和归一化循环做向量化。
- 最后理解 SIMD 适合处理“规则、连续、边界清晰”的数据通路。

## 运行

```bash
make run
./simd_layernorm 256 4096
```

参数含义：

- `rows`：矩阵行数，默认 `256`
- `cols`：每行特征数，默认 `4096`

## 文件结构

| 文件 | 说明 |
|------|------|
| `layernorm_serial.c` | 串行 LayerNorm，作为黄金参考 |
| `layernorm_simd.c` | `omp simd` 版本，展示向量化归约与归一化 |
| `main.c` | 对比驱动：计时 + 校验 + 加速比报告 |
| `layernorm.h` | 公共声明 |
| `Makefile` | 仅需 OpenMP 即可构建 |

## 教学要点

- 这个实验不是在讲“并行线程”，而是在讲“单个线程内部如何继续榨干算力”。
- LayerNorm 是典型的 ML 归一化算子，适合把 SIMD 和实际模型算子联系起来。
- 第6章的重点不是手写每一条 SIMD 指令，而是建立“编译器能不能看懂你的循环”的判断能力。
- 这个实验也适合和第9章、`ch10_fused_softmax` 一起看，理解向量化在 ML 系统中的位置。

## 推荐观察

1. 改变 `cols`，观察对齐和向量宽度是否影响收益。
2. 固定 `rows`，改变 `cols` 为 `1024 / 2048 / 4096 / 8192`，看向量化收益是否更稳定。
3. 对比串行和 SIMD 版本的结果，确认向量化没有破坏数值正确性。

## 动手实验

1. 把第二个循环改成普通 `for`，观察 `omp simd` 到底帮你省了什么。
2. 把 `cols` 改成不是 2 的幂，观察循环尾部处理是否影响性能。
3. 如果编译器支持，尝试 `-march=native` 和不开启时的差异。
