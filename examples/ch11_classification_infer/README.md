# 教学实验：图像分类推理与量化部署

> 对应章节：第11章。这个实验把一个分类模型的“导出 -> 量化 -> 转换 -> 推理”串成教学契约闭环，用来固定阶段接口、报告字段和失败边界；默认输出不代表真实后端测量。

## 实验目标

- 先把单模型推理链路拆成可检查的阶段。
- 再比较量化前后、不同后端报告应包含哪些精度与耗时字段。
- 最后理解为什么图像分类是最适合入门推理部署的任务类型之一。

## 运行入口

```bash
make run
make convert-rknn
make convert-ascend
```

默认流程是：

```bash
python3 01_export_onnx.py
python3 02_quantize.py
python3 04_infer.py
```

## 目录结构

| 路径 | 说明 |
|---|---|
| `01_export_onnx.py` | 导出 ONNX 工件清单 |
| `02_quantize.py` | 量化与校准报告 |
| `03_convert_rknn.py` / `03_convert_ascend.sh` | 平台相关转换入口 |
| `04_infer.py` | 推理与报告生成 |
| `models/` | 模型约定与接入模板 |
| `data/` | 校准集和测试集说明 |
| `artifacts/` | 中间工件和报告输出 |

## 教学要点

- 量化不是单独优化，它和校准集、输入分布、后端限制强相关。
- 部署不是把模型“扔给工具链”，而是把输入、输出、格式和检查项提前冻结。
- 推理实验里最值得观察的，不只是 latency，还包括 top1 / top5 和量化误差趋势。

## 证据边界

默认脚本生成的是 `simulated` / `teaching_profile` 报告：它证明导出、量化、转换和推理阶段的接口可以衔接，不能证明 RKNN、昇腾或 TensorRT 的真实兼容性、精度或延迟。真实后端必须在目标设备上导入厂商运行时报告，并记录模型、输入、运行时版本和测量口径。

## 推荐观察

1. 先看导出报告，确认模型名、输入输出张量和预处理约定是否固定。
2. 再看量化报告，确认校准集数量和后端配置是否记录完整。
3. 最后看推理报告，对比不同后端的 latency 和 accuracy 指标。

## 动手实验

1. 先用 `resnet18` 跑通默认流程，再替换成自己的分类模型。
2. 调整 `data/calib/list.txt`，观察量化报告和推理报告是否变化。
3. 对比 `rknn`、`ascend` 和 `tflite` 三个后端的报告格式和指标差异。
