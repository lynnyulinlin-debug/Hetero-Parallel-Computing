# 教学实验：NPU 模型部署脚手架

> 对应章节：第11章。这个实验把分类模型的导出、量化、转换和板端推理拆成可维护阶段，用来理解部署链路为什么必须先冻结接口再接厂商工具。

## 实验目标

- 先把模型接入约定、目录约定和报告格式固定下来。
- 再理解导出、量化、转换和推理分别在解决什么问题。
- 最后把部署链路看成一条可检查的教学脚手架，而不是一次性脚本。

## 运行入口

```bash
make run
make convert-rknn
make convert-ascend
```

默认流程是：

```bash
python3 01_export_onnx.py
python3 02_quantize.py
python3 04_infer.py
```

## 目录结构

| 路径 | 说明 |
|---|---|
| `01_export_onnx.py` | 导出阶段脚手架 |
| `02_quantize.py` | 量化与校准阶段脚手架 |
| `03_convert_rknn.py` / `03_convert_ascend.sh` | 平台相关转换入口 |
| `04_infer.py` | 板端推理与结果汇总 |
| `models/` | 模型说明与接入模板 |
| `data/` | 校准集和测试集说明 |
| `artifacts/` | 导出、量化和推理报告 |

## 教学要点

- 这个实验的重点不是立刻跑通某个真实板子，而是把部署阶段的边界提前冻结。
- 平台无关层先固定输入、模型和报告格式，平台相关层再接厂商工具。
- 量化和转换的意义，在于把训练好的模型变成板端可运行、可验证的工件。

## 推荐观察

1. 先看导出报告，再看量化报告，最后看推理报告。
2. 把校准集和测试集分开，观察样本数量和输入分布是否会影响结果解释。
3. 对照不同后端的转换入口，理解为什么同一模型在不同平台上要走不同路径。

## 动手实验

1. 先用 `resnet18` 跑通整个脚手架，再替换成自己的模型。
2. 调整 `data/calib/list.txt`，观察量化报告是否变化。
3. 把 `models/real_model_template.md` 当作新模型接入模板，填一份自己的部署说明。
